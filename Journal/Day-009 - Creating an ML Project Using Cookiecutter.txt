# 🚧 Challenge 1 - Missing `ml_framework` Variable

I checked the original `cookiecutter.json` file:

```bash
cat cookiecutter.json
```

The original content was:

```json
{
    "project_name": "my-ml-project",
    "author": "xFusionCorp",
    "python_version": "3.11"
}
```

## ❌ Problem

The task required four variables, but the original file only contained three:

```text
project_name
author
python_version
```

The following variable was missing:

```text
ml_framework
```

Without this variable, Cookiecutter could not ask the user which machine learning framework to use.

---

## ✅ Solution

I edited the file using:

```bash
nano cookiecutter.json
```

I added the missing variable:

```json
{
    "project_name": "my-ml-project",
    "author": "xFusionCorp",
    "python_version": "3.11",
    "ml_framework": ["sklearn", "pytorch", "tensorflow"]
}
```

After saving the file, I verified it:

```bash
cat cookiecutter.json
```

The corrected configuration was:

```json
{
    "project_name": "my-ml-project",
    "author": "xFusionCorp",
    "python_version": "3.11",
    "ml_framework": ["sklearn", "pytorch", "tensorflow"]
}
```

# 🚧 Challenge 2 - Understanding Cookiecutter Choices

Initially, I was unsure how to define multiple choices for `ml_framework`.

I learned that when a Cookiecutter variable is defined as a list:

```json
"ml_framework": ["sklearn", "pytorch", "tensorflow"]
```

Cookiecutter presents the options interactively.

When I ran the template, Cookiecutter displayed:

```text
[4/4] Select ml_framework
    1 - sklearn
    2 - pytorch
    3 - tensorflow
    Choose from [1/2/3] (1):
```

This allowed me to choose the required framework.

For this task, I selected:

```text
1
```

which represented:

```text
sklearn
```

---

# 🚧 Challenge 3 - Conditional Dependency Logic

The next requirement was to make the generated `requirements.txt` change according to the selected framework.

The required behavior was:

```text
sklearn     → scikit-learn
pytorch     → torch
tensorflow  → tensorflow
```

I used Jinja2 conditional logic inside the template:

```jinja2
{% if cookiecutter.ml_framework == "sklearn" %}
scikit-learn
{% elif cookiecutter.ml_framework == "pytorch" %}
torch
{% elif cookiecutter.ml_framework == "tensorflow" %}
tensorflow
{% endif %}
```

This is important because the file inside the template is not a normal static requirements file.

It is a template.

Cookiecutter evaluates the selected value and generates the correct dependency.

For example:

```text
Selected framework: sklearn
```

Generated:

```text
scikit-learn
```

If the selected framework had been:

```text
pytorch
```

the generated file would contain:

```text
torch
```

And if the selected framework had been:

```text
tensorflow
```

the generated file would contain:

```text
tensorflow
```

# 🚧 Challenge 4 - Dynamic README Content

The README also needed to use values selected during project generation.

The template used Cookiecutter variables:

```markdown
# {{ cookiecutter.project_name }}

This machine learning project was created by {{ cookiecutter.author }}.

Python version: {{ cookiecutter.python_version }}

Machine Learning Framework: {{ cookiecutter.ml_framework }}
```

These values are replaced automatically when Cookiecutter generates the project.

For example:

```text
project_name = churn-model
author = xFusionCorp
python_version = 3.11
ml_framework = sklearn
```

becomes:

```markdown
# churn-model

This machine learning project was created by xFusionCorp.

Python version: 3.11

Machine Learning Framework: sklearn
```

---

# 🧠 Understanding Cookiecutter Variables

Cookiecutter uses template variables with this syntax:

```text
{{ cookiecutter.variable_name }}
```

For example:

```text
{{ cookiecutter.project_name }}
```

is replaced with the value selected by the user.

If the user enters:

```text
churn-model
```

the generated project directory becomes:

```text
churn-model
```

This allows one template to generate many different projects.

For example, the same template could generate:

```text
fraud-detection/
```

or:

```text
customer-churn/
```

or:

```text
image-classification/
```

without manually recreating the project structure each time.

# 🧠 Important Concepts

## Cookiecutter

Cookiecutter is a project templating tool.

It allows developers to create a standard project structure once and reuse it multiple times.

---

## `cookiecutter.json`

This file defines the variables that users can customize when generating a project.

Example:

```json
{
    "project_name": "my-ml-project",
    "author": "xFusionCorp",
    "python_version": "3.11",
    "ml_framework": ["sklearn", "pytorch", "tensorflow"]
}
```

---

## Jinja2 Variables

This:

```text
{{ cookiecutter.project_name }}
```

is replaced by the selected project name.

---

## Jinja2 Conditional Logic

This:

```jinja2
{% if cookiecutter.ml_framework == "sklearn" %}
scikit-learn
{% elif cookiecutter.ml_framework == "pytorch" %}
torch
{% elif cookiecutter.ml_framework == "tensorflow" %}
tensorflow
{% endif %}
```

allows the generated content to change based on the selected framework.
